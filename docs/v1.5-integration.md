# Cahier d'intégration — v1.5

## Fonctionnalités demandées

1. Connexion facultative au compte Google choisi par chaque utilisateur Android.
2. Sauvegarde sur **son propre Drive** des profils, pesées, objectifs et journal alimentaire.
3. Réutilisation du même fichier de sauvegarde (pas de doublons à chaque modification).
4. Invitation directement dans l'app à une adresse Google, avec permission **reader** Google Drive.
5. Profil partagé lisible sans pouvoir modifier pesées, repas, objectif ou photos.
6. Actualisation à l'ouverture, bouton manuel et rafraîchissement périodique si l'app est active ; ne pas promettre du temps réel strict.
7. Révocation des invitations depuis l'app, avec suppression de permission Google Drive.
8. Option facultative **inclure les photos des repas**, désactivée par défaut.
9. Conservation des profils locaux existants, historique et exports mensuels PDF.
10. Nom affiché « Mon Évolution IMC », écran À propos et fichiers APK versionnés.

## Modèle de stockage (proposé)

- Un fichier privé de sauvegarde par propriétaire pour restaurer tous ses profils.
- **Un fichier partagé distinct par profil**, avec données minimisées, pour éviter d'exposer les autres profils.
- Le propriétaire conserve la permission d'écriture et attribue aux invités une permission `reader` nominative.
- Ne pas utiliser « Tous les utilisateurs disposant du lien ».
- Conserver le file ID dans le stockage privé Android ; mise à jour par ID avec `files.update`, pas création répétée.
- Suivre date de dernière synchronisation, conflits, échecs et mode hors ligne ; ne pas détruire une sauvegarde existante en cas de conflit.
- Un lien d'invitation seul ne remplace **pas** une permission Google Drive ; le compte connecté de l'invité doit être autorisé.

## OAuth et Google Cloud

- Projet Google Cloud existant : `mon-evolution`.
- Portée demandée : `https://www.googleapis.com/auth/drive.file` (accès limité aux fichiers ouverts/créés par l'app).
- Le client OAuth Android utilise l'identifiant de package `fr.monevolution.app` et l'empreinte SHA-1 de **l'APK de sortie**.
- Utiliser un flux OAuth/SDK Google pour Android maintenu, sans insérer de client secret dans une APK.
- Pour l'ouverture à tous, configurer Audience **Externe / Production**, et respecter les exigences de Google concernant le branding, le domaine, et la validation éventuelle.
- Le simple sélecteur de fichiers Android (Storage Access Framework) ne suffit pas pour attribuer/revoquer des permissions Drive par e-mail ; une intégration OAuth/API est nécessaire.
